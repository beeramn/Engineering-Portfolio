Smart Pace-Setter Line-Following Car

An autonomous running companion that follows a track lane while maintaining a user-selected pace. The system combines QTI line sensing, encoder-based speed feedback, two communicating ESP32 units, and a proof-of-concept cloud logging pipeline.

Project Overview

Goal

Build a small autonomous car that travels alongside a runner, follows a marked track lane, and regulates its speed to a selected pace in minutes per mile. A touchscreen controller sends the pace and start/stop commands to the vehicle.

Two-Controller Design

The Controller ESP handles the touchscreen interface and sends user commands. The Car ESP reads the QTI sensor array and wheel encoder, calculates steering and motor outputs, and runs the real-time control logic. The ESP32s communicate directly over ESP-NOW without an external router.

Project Context

Developed for ECE 655 by Flaviana Keller, Brandon Ramirez, and Neyla Kirby. The line-following and pace-setting subsystems were demonstrated and tested independently.

System Architecture and Hardware

Car Controller

An ESP32-S3 runs ESP-IDF and FreeRTOS. It reads the QTI reflectance array and magnetic wheel encoder, then controls the steering servo and motor driver using PWM.

User Controller

A second ESP32 provides pace selection and start/stop controls through a touchscreen interface. LVGL supports the optional user interface, and ESP-NOW carries commands to the car.

Motor and Steering

A 12 V RS-550 DC motor and BTS7960 / IBT-2 motor driver propel the RC chassis. A steering servo moves the front assembly; software filtering smooths commands when the sensor readings change.

Power

A 3S Zeee 5200 mAh LiPo battery supplies the primary rail. A ZK-4KX buck converter steps voltage down for the ESP32, servo, and driver logic. The ESP32's 3.3 V output powers the QTI array and magnetic encoder; fuses help protect against high current during stalls.

Line Following and Pace Regulation

Weighted Line-Position Estimate

The QTI array sits about one inch above the track. Its eight binary light/dark readings receive position weights from -350 on the left to +350 on the right. A weighted average estimates the line's offset from the center of the car; the resulting error determines the steering direction and PWM.

Steering Smoothing

The filter retains about 75% of the previous steering command and adds 25% of the new command to reduce jitter. If the sensor array temporarily loses the line, the car retains its last steering command while attempting to reacquire the track.

Encoder-Based Speed

A Hall-effect encoder reads a magnet mounted to the rear wheel axle. Eight transitions represent one wheel revolution. With a wheel diameter near 0.115 m, each count corresponds to approximately 0.045 m of travel.

PI Speed Control

The selected pace is converted from minutes per mile to meters per second. The controller compares the ramped target with filtered encoder speed, uses proportional and integral terms, resets the integrator at zero target, and applies anti-windup and a 60% PWM output limit.

The main control loop runs every 20 ms. Speed is estimated over a 100 ms window and low-pass filtered to reduce jumps caused by discrete encoder pulses. Startup ramps speed gradually, while stopping ramps it down more quickly.

Wireless Communication and Data Logging

ESP-NOW Commands

The controller sends pace, start, and stop commands directly to the car ESP32 over ESP-NOW. This allows the car to operate without depending on a Wi-Fi router or external network for its real-time control path.

Cloud Logging Proof of Concept

At the end of a run, the controller can package start time, end time, and selected pace as JSON and send it through an HTTP POST request. A Python Flask /sensor endpoint parses the payload and stores the values in PostgreSQL.

Validation Status

The ESP32-to-server pipeline was validated with dummy data and confirmed to insert records into the database. Consistent real-world run data was not collected because of mechanical reliability problems with the RC platform.

Challenges and Next Steps

Sensor Lighting

QTI performance changed under low or variable lighting. Improved calibration or directed illumination near the array could make line detection more consistent.

Mechanical Binding

Friction around the encoder-side wheel caused the encoder to under-report speed. The PI controller responded by increasing motor output, which raised mechanical stress and could lead to stalls and current spikes. A more balanced wheel assembly is a priority.

Steering Response

Stiff joints initially delayed steering motion. Lubricating the front assembly improved response, while digital low-pass filtering reduced servo jitter from noisy sensor readings.

Future Work

Planned improvements include redesigning the encoder-side wheel, determining a higher safe speed, improving QTI calibration and lighting, strengthening power efficiency, and fully integrating real-run logging and visualization.
