Custom 32-Bit Pipelined Processor on FPGA

A custom five-stage, single-issue processor built in structural Verilog and deployed on a Xilinx FPGA at 100 Mhz. The processor's memory-mapped I/O controls a claw machine built by repurposing a PlasticFab-3B 12-cubed platform.

Project Overview

Objective

Design and deploy a 32-bit pipelined processor that can run an assembly program and interact with external hardware. The claw machine serves as the application; the central engineering work is the processor datapath, pipeline control, hazard handling, instruction execution, and hardware/software interface.

System Components

The system brings together a program counter, instruction and data memories, register file, ALU, multicycle multiplication and division unit, pipeline control, assembly software, and memory-mapped hardware I/O.

Processor Architecture

The CPU is single-issue and uses F/D, D/X, X/M, and M/W pipeline latches between its five stages. Separate word-addressed instruction and data memories keep instruction fetch distinct from data access.

1. Fetch

The program counter addresses instruction memory and normally increments by one because memory is word-addressed. After reset, execution starts at address zero.

2. Decode

Decode interprets the opcode and fields, reads source registers, and creates control signals. Branch and jump decisions are coordinated here without delay slots.

3. Execute

The ALU performs arithmetic, logic, comparisons, and branch decisions, with overflow detection and exception generation. Multiply and divide use a separate multicycle path.

4. Memory

The memory stage handles word loads and stores and connects software to data memory and the memory-mapped peripheral interface.

5. Writeback

The destination register receives the selected ALU result, memory value, MultDiv result, or control-flow result.

Hazard Handling

Forwarding resolves read-after-write dependencies when possible. The control logic stalls for load-use dependencies and holds fetch/decode while MultDiv is busy. Taken branches and jumps redirect the PC and suppress the following instruction.

Register File

The register file has two read ports and one write port. $r0 is hardwired to zero, $r30 stores status and exception codes, and $r31 holds the return address for jal.

MultDiv Unit

Multiplication and division are iterative operations coordinated with the pipeline. The processor waits for the ready signal before committing a result; one-cycle control pulses prevent a stall from accidentally restarting an operation.

Exceptions

Arithmetic overflow and exception handling use the status register. The instruction set includes bex and setx for exception and status control.

Motion System

The repurposed PlasticFab-3B 12-cubed printed platform provides much of the XYZ structure. NEMA 17 stepper motors use external driver modules; step pulses advance the motors and direction signals select travel direction. Verilog PWM serializers generate motor pulses while assembly tracks logical positions.

Inputs and Sensors

A joystick requests X/Y movement, a push button starts the game and drop sequence, X/Y limit switches detect mechanical boundaries, and an IR break-beam sensor supplies object or position feedback. Limit-switch handling resets tracked position and moves an axis away from a triggered boundary.

Claw and Effects

The claw motor is controlled separately from XYZ motion through $r13, with state feedback through $r16. Independently added LEDs and application-level music run during the celebration sequence.

Software Calibration

These values are application settings that depend on the machine geometry, cable, motor speed, driver settings, and pulley arrangement; they are not fixed properties of the processor.

Assembly-Controlled Operating Cycle

The assembly program handles sequencing, timing, state tracking, boundary checks, and decisions. Peripheral logic translates processor outputs into electrical signals for the motors, claw, LEDs, and music.

  1. Start with the X, Y, and Z drivers disabled, then wait for the start button.
  2. On the first press, initialize position and delay counters and raise the claw to its starting height.
  3. Use joystick input to position the claw in X and Y; direction counters pace position updates.
  4. On the second press, disable X/Y movement and begin lowering the claw along Z.
  5. At the Z position limit, close the claw, reverse Z motion, and raise the claw.
  6. Return the X/Y mechanism toward its starting position using software position tracking and limit-switch feedback.
  7. Open the claw to release the object, then run the independent LED and music celebration behavior.

Assembly Demonstration

The program initializes outputs, polls mapped inputs, updates position state, checks boundaries, and branches through start, wait, move, drop, close, rise, return, and celebration states. This exercises arithmetic, register dependencies, branches, loops, and memory-mapped I/O in software.

Verification and FPGA Deployment

The processor is deployed on a Xilinx FPGA at 100 Mhz. The following areas form the system verification checklist described for the project.

Processor Modules

Check ALU operations, register-file reads and writes, instruction decode, and status-register behavior.

Pipeline Control

Exercise forwarding, load-use stalls, taken and not-taken branches, jumps, MultDiv completion, and pipeline holding.

Integrated System

Check reset and PC initialization, memory-mapped reads and writes, and assembly execution with simulated peripheral inputs.

Hardware Bring-Up

Use Vivado/XSim simulation and check timing at 100 Mhz. During bring-up, verify the CPU and mapped registers before connecting motors; test peripherals one at a time and confirm limit-switch behavior and driver-disable polarity.
